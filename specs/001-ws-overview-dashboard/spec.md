## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전체 시스템 상태 한눈에 파악 (Priority: P1)

운영자가 워크스페이스의 전반적인 건강 상태를 대시보드에 접근하자마자 즉시 파악할 수 있다. 상단 요약 카드에서 전체 Health 상태, 활성 에이전트 수, 현재 알림 수를 확인하여 시스템에 문제가 있는지 빠르게 인지한다.

**Why this priority**: 대시보드의 핵심 목적은 시스템 상태를 빠르게 파악하는 것이므로 가장 높은 우선순위

**Independent Test**: 대시보드 페이지 로드 시 3개의 요약 카드가 실시간 데이터와 함께 표시되는지 확인하여 테스트 가능

**Acceptance Scenarios**:

1. **Given** 사용자가 워크스페이스에 접근했을 때, **When** Overview 대시보드를 열면, **Then** 전체 Health(정상/경고/위험), 활성 Agent 수(활성/전체), 현재 Alert 수(위험/중요)가 카드 형태로 표시된다
2. **Given** 시스템 데이터가 갱신되었을 때, **When** 실시간 업데이트가 발생하면, **Then** 요약 카드의 수치가 자동으로 갱신된다
3. **Given** 전체 Health가 정상 상태일 때, **When** 대시보드를 보면, **Then** Health 카드에 초록색 체크 아이콘과 "정상" 텍스트, 퍼센티지(예: 98.5%)가 표시된다

---

### User Story 2 - Agent 상태 모니터링 (Priority: P1)

운영자가 개별 에이전트들의 상태와 부하를 확인하여 특정 에이전트에 문제가 있는지 파악한다. 에이전트별 위치(서버)와 Load 퍼센티지를 한눈에 볼 수 있다.

**Why this priority**: 에이전트 상태는 APM 모니터링의 핵심 기능으로, 문제 발생 시 어느 에이전트에서 발생했는지 파악이 필수적

**Independent Test**: Agent 상태 요약 위젯이 에이전트 목록과 각각의 Load 값을 표시하는지 확인

**Acceptance Scenarios**:

1. **Given** 워크스페이스에 복수의 에이전트가 등록되어 있을 때, **When** Agent 상태 요약 섹션을 보면, **Then** 각 에이전트의 이름, 위치(도시명), Load 퍼센티지가 테이블 형태로 표시된다
2. **Given** 에이전트의 상태가 정상/경고/위험일 때, **When** 해당 에이전트를 보면, **Then** 상태에 따른 색상 인디케이터(초록/노랑/빨강)가 표시된다
3. **Given** 활성 에이전트가 많을 때, **When** 목록을 보면, **Then** "총 N개 활성" 레이블과 함께 페이지네이션 또는 스크롤로 전체 목록 확인 가능

---

### User Story 3 - 핵심 성능 지표 확인 (Priority: P1)

운영자가 TPS, Error Rate, Avg Response Time 등 핵심 성능 지표를 확인하여 애플리케이션의 성능 상태를 파악한다. 각 지표별 변화량도 함께 표시되어 이전 대비 상태를 알 수 있다.

**Why this priority**: 성능 지표는 서비스 품질의 핵심 메트릭으로 운영자가 반드시 모니터링해야 하는 항목

**Independent Test**: 성능 지표 위젯이 TPS, Error Rate, Avg Response를 수치와 변화량과 함께 표시하는지 확인

**Acceptance Scenarios**:

1. **Given** 대시보드가 로드되었을 때, **When** 성능 지표 섹션을 보면, **Then** TPS(초당 트랜잭션), Error Rate(%), Avg Response(ms)가 각각 아이콘, 수치, 단위와 함께 표시된다
2. **Given** 성능 지표가 이전 기간 대비 변화했을 때, **When** 해당 지표를 보면, **Then** 변화량이 +/- 퍼센트 또는 절대값으로 표시되며 증가/감소에 따른 색상(초록/빨강)이 적용된다
3. **Given** Error Rate가 정상 범위(예: 0.5% 이하)일 때, **When** 해당 지표를 보면, **Then** 초록색 계열로 표시되고, 비정상 범위일 때는 빨강색으로 표시된다

---

### User Story 4 - 리소스 사용률 모니터링 (Priority: P2)

운영자가 CPU 사용률, Memory 사용률, 동시 사용자 수를 확인하여 인프라 리소스 상태를 파악한다. 각 리소스별 세부 항목(전일/전주/전월 대비)도 확인할 수 있다.

**Why this priority**: 리소스 사용률은 시스템 용량 계획과 문제 예방에 중요하지만, 성능 지표보다는 후순위

**Independent Test**: 리소스 사용률 위젯이 CPU, Memory, 동시 사용자를 프로그레스 바와 세부 비교 데이터와 함께 표시하는지 확인

**Acceptance Scenarios**:

1. **Given** 대시보드가 로드되었을 때, **When** 리소스 사용률 섹션을 보면, **Then** CPU 사용률(%), Memory 사용률(%), 동시 사용자(명)가 각각 카드 형태로 표시된다
2. **Given** 각 리소스 카드를 볼 때, **When** 세부 정보를 확인하면, **Then** 전일/전주/전월 대비 변화량이 +/- 형태로 표시된다
3. **Given** 리소스 사용률이 표시될 때, **When** 카드를 보면, **Then** 프로그레스 바로 현재 사용률이 시각화되며 임계치(예: 80%)를 넘으면 색상이 변경된다

---

### User Story 5 - 시계열 차트로 추이 확인 (Priority: P2)

운영자가 TPS 추이, Agent 활성 추이, Error 추이를 시계열 차트로 확인하여 시간에 따른 패턴과 이상 징후를 파악한다.

**Why this priority**: 추이 차트는 현재 상태보다는 분석적 관점에서 유용하므로 핵심 지표보다 후순위

**Independent Test**: 3개의 시계열 차트가 24시간 데이터를 라인 차트로 표시하는지 확인

**Acceptance Scenarios**:

1. **Given** 대시보드가 로드되었을 때, **When** 추이 차트 섹션을 보면, **Then** TPS 추이(24시간), Agent 활성 추이, Error 추이가 각각 라인 차트로 표시된다
2. **Given** 차트가 표시될 때, **When** X축을 보면, **Then** 시간대(1:00, 3:00, ... 23:00)가 표시되고 Y축에는 해당 메트릭의 수치가 표시된다
3. **Given** 차트 위에 마우스를 올렸을 때, **When** 특정 시점을 가리키면, **Then** 툴팁으로 해당 시점의 정확한 수치가 표시된다

---

### User Story 6 - Top Alerts 확인 (Priority: P2)

운영자가 최근 발생한 주요 알림들을 목록으로 확인하여 즉각적인 대응이 필요한 이슈를 파악한다.

**Why this priority**: 알림 목록은 문제 인지 후 대응에 필요하므로 상태 확인보다 후순위

**Independent Test**: Top Alerts 위젯이 알림 목록을 심각도, 메시지, 발생 시간과 함께 표시하는지 확인

**Acceptance Scenarios**:

1. **Given** 대시보드가 로드되었을 때, **When** Top Alerts 섹션을 보면, **Then** 최근 알림이 목록 형태로 표시되며 각 알림에는 서비스명, 메시지, 발생 시간이 포함된다
2. **Given** 알림의 심각도가 다를 때, **When** 목록을 보면, **Then** 심각도에 따른 아이콘/색상(빨강-위험, 노랑-경고, 파랑-정보)이 표시된다
3. **Given** 알림이 있을 때, **When** 헤더를 보면, **Then** "N개 활성" 버튼이 표시되어 전체 알림 페이지로 이동할 수 있다

---

### User Story 7 - Risk Services 확인 (Priority: P2)

운영자가 위험 상태의 서비스들을 목록으로 확인하여 임계치를 초과한 서비스에 대해 인지하고 대응한다.

**Why this priority**: Risk Services는 문제 서비스를 집중 모니터링하는 데 유용하지만 전체 상태 파악보다 후순위

**Independent Test**: Risk Services 위젯이 위험 서비스 목록을 사유, 사용률과 함께 표시하는지 확인

**Acceptance Scenarios**:

1. **Given** 대시보드가 로드되었을 때, **When** Risk Services 섹션을 보면, **Then** 위험 상태의 서비스가 목록으로 표시되며 각 서비스에는 이름, 위험 사유, 현재 수치(%)가 포함된다
2. **Given** 서비스의 위험 수준이 다를 때, **When** 목록을 보면, **Then** 심각도에 따른 레이블(위험/중간)과 색상이 표시된다
3. **Given** 서비스의 사용률이 표시될 때, **When** 해당 항목을 보면, **Then** 프로그레스 바로 현재 사용률이 시각화되며 임계치 초과 영역이 다른 색상으로 표시된다

---

### Edge Cases

- 에이전트가 하나도 등록되지 않은 워크스페이스에서는 어떻게 표시되는가? → 빈 상태 안내 메시지 표시
- 실시간 데이터 수신이 실패했을 때 어떻게 처리되는가? → 마지막 정상 데이터 유지 + 연결 상태 표시
- 알림이 하나도 없을 때 Top Alerts 섹션은 어떻게 표시되는가? → "활성 알림 없음" 메시지 표시
- 성능 지표 데이터가 아직 수집되지 않은 신규 워크스페이스의 경우? → "데이터 수집 중" 상태 표시
- 동시 사용자가 매우 많아 수치가 길어질 경우? → K/M 단위로 축약 표시 (예: 1,842 → 1.8K)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 반드시 실시간으로 전체 Health 상태(정상/경고/위험), Health 퍼센티지, 상태 아이콘을 요약 카드로 표시해야 한다
- **FR-002**: 시스템은 반드시 활성 Agent 수와 전체 Agent 수를 "N / M" 형식으로 표시하고 활성화율(%)을 함께 표시해야 한다
- **FR-003**: 시스템은 반드시 현재 Alert 수를 심각도별(위험/중요)로 분류하여 표시해야 한다
- **FR-004**: 시스템은 반드시 Agent 상태 요약 테이블에서 각 에이전트의 이름, 위치, Load 퍼센티지, 상태 인디케이터를 표시해야 한다
- **FR-005**: 시스템은 반드시 성능 지표(TPS, Error Rate, Avg Response)를 수치와 단위, 직전 1시간 대비 변화량과 함께 표시해야 한다
- **FR-006**: 시스템은 반드시 리소스 사용률(CPU, Memory, 동시 사용자)을 프로그레스 바와 세부 비교 데이터(전일/전주/전월)와 함께 표시해야 한다
- **FR-007**: 시스템은 반드시 TPS 추이, Agent 활성 추이, Error 추이를 24시간 시계열 라인 차트로 표시해야 한다
- **FR-008**: 시스템은 반드시 Top Alerts 목록에서 서비스명, 알림 메시지, 발생 시간, 심각도를 표시해야 한다
- **FR-009**: 시스템은 반드시 Risk Services 목록에서 서비스명, 위험 사유, 현재 수치(%), 프로그레스 바를 표시해야 한다
- **FR-010**: 시스템은 반드시 실시간 업데이트 표시("실시간 업데이트" 라벨)를 헤더에 표시해야 한다
- **FR-011**: 시스템은 반드시 데이터 로딩 중에는 로딩 상태를 표시하고, 에러 발생 시 재시도 옵션을 제공해야 한다
- **FR-012**: 사용자는 반드시 대시보드 페이지에 접근하여 모든 위젯을 한 화면에서 확인할 수 있어야 한다

### Key Entities

- **Health Summary**: 워크스페이스의 전반적인 건강 상태 (상태, 퍼센티지, 아이콘)
- **Agent Summary**: 에이전트의 상태 정보 (이름, 위치, Load, 상태)
- **Performance Metrics**: 성능 지표 데이터 (TPS, Error Rate, Avg Response, 변화량)
- **Resource Usage**: 리소스 사용률 데이터 (CPU, Memory, 동시 사용자, 비교 데이터)
- **Alert**: 알림 정보 (서비스명, 메시지, 발생 시간, 심각도)
- **Risk Service**: 위험 서비스 정보 (서비스명, 위험 사유, 현재 수치, 심각도)
- **Time Series Data**: 시계열 차트 데이터 (시간, 메트릭 값)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대시보드 페이지 로드 후 3초 이내에 모든 요약 카드와 위젯이 데이터와 함께 표시된다
- **SC-002**: 실시간 데이터 업데이트가 5초 간격으로 자동 갱신되며 사용자가 새로고침 없이 최신 상태를 확인할 수 있다
- **SC-003**: 운영자가 시스템 이상 상태를 인지하는 데 걸리는 시간이 10초 이내이다 (요약 카드를 통한 즉각적 인지)
- **SC-004**: 모든 시계열 차트가 24시간 데이터를 정확하게 표시하며, 툴팁을 통해 상세 수치 확인이 가능하다
- **SC-005**: 위험/경고 상태의 에이전트, 알림, 서비스가 시각적으로 명확하게 구분되어 운영자가 즉시 식별할 수 있다

## Assumptions

- 워크스페이스 ID(wsid)는 URL 파라미터로 전달된다고 가정
- 실시간 데이터 갱신 주기는 5초로 가정
- 시계열 차트의 기본 범위는 24시간으로 가정
- Health 상태의 임계치는 기존 시스템 설정을 따른다고 가정
- 리소스 사용률의 전일/전주/전월 비교 데이터는 백엔드에서 계산되어 제공된다고 가정
